## 1. Introduction

### 1.1 Document Purpose

Esta SRS define los requisitos verificables para completar el subsistema de
internacionalización (i18n) español/inglés de Xclusive Barber Academy. El
propósito es cerrar la brecha identificada: el conmutador de idioma funciona en
la landing pública, pero las pantallas internas (dashboard, cursos, tracker,
grading, progreso profesional y admin) permanecen en español porque contienen
texto hardcodeado y contenido de base de datos no localizado.

Las audiencias de este documento son: **producto** (alcance y prioridades),
**ingeniería** (El Ejecutor — contratos de implementación), **QA** (criterios de
aceptación y matriz de verificación) y **operaciones** (migración de base de
datos). El documento define *qué* debe hacer el sistema, no *cómo* implementarlo;
los detalles de implementación se entregan como contratos y reglas
arquitectónicas para el agente ejecutor.

### 1.2 Product Scope

**Producto:** Xclusive Barber Academy — plataforma de formación en barbería
(Next.js 15 App Router + Supabase Postgres).

**Alcance de esta SRS (inclusiones):**

1. Traducción completa de la *carcasa de UI* (UI chrome) de toda la aplicación:
   textos fijos de interfaz — botones, etiquetas, headers, tarjetas, estados
   vacíos, estados de carga/error y tooltips — en las áreas de dashboard, cursos,
   lecciones, tracker, grading, progreso profesional y administración.
2. Traducción de los **títulos y descripciones de contenido** (nombres de módulos,
   títulos de lecciones, descripciones de módulos) mediante columnas traducidas
   (`*_en`) en Supabase con *fallback* al español.
3. Localización de los **nombres de competencias** y **niveles profesionales** por
   idioma activo.
4. Documentación del subsistema i18n en la documentación del proyecto.

**Exclusiones explícitas (fuera de alcance, diferidas — véase 2.6):**

- El **contenido HTML rich-text** de cada lección (`lessons.content`, editor
  Tiptap) permanece en español (idioma de autoría).
- El **feedback generado por IA** (`submissions.feedback_ai`, `cut_type`,
  descripciones de envíos de estudiantes) permanece en español.
- No se introduce enrutamiento por prefijo de URL (ej. `/en/...`). El idioma
  sigue determinándose por cookie + `accept-language` (mecanismo existente).
- No se migra a una librería externa (next-intl, react-i18next); se conserva el
  diccionario tipado propio.

### 1.3 Definitions, Acronyms, and Abbreviations

| Term | Definition |
|------|------------|
| UI chrome | Textos fijos de interfaz (botones, etiquetas, headers, estados) distintos del contenido del dominio |
| i18n | Internationalization — diseño que permite mostrar el producto en múltiples idiomas |
| RSC | React Server Component — componente renderizado en el servidor, sin JavaScript en el navegador |
| Diccionario | Mapa tipado `es`/`en` en `lib/i18n/dictionaries.ts` que contiene las cadenas de UI |
| Columna `*_en` | Columna de la BD que almacena la traducción al inglés de un campo textual; la columna base (`title`, `description`) conserva el español |
| Fallback | Regla por la que, si una traducción es `null`/vacía, se muestra el valor en español |
| Supabase | Plataforma Postgres gestionada (auth, storage, RLS, edge functions) |
| Zebra stripes | No aplica (término desambiguado) |

## 2. Product Overview

### 2.1 Product Perspective

El producto ya dispone de un subsistema i18n propio (no basado en una librería de
terceros), introducido históricamente para la landing y los headers. Está
compuesto por:

- `lib/i18n/config.ts` — idiomas soportados (`es`, `en`), cookie `preferred_language`, resolución desde `accept-language`.
- `lib/i18n/server.ts` — helpers RSC `getServerLanguage()` / `getServerDictionary()` (con `React.cache`).
- `lib/i18n/dictionaries.ts` — diccionario tipado (`as const`) con ramas `es` y `en`.
- `components/i18n/LanguageProvider.tsx` — contexto React (`useLanguage`) para componentes cliente.
- `components/i18n/LanguageSwitcher.tsx` + `FloatingLanguageSwitcher.tsx` — UI del conmutador.
- `app/i18n/actions.ts` — Server Action `setLanguagePreference` que persiste la cookie y llama `revalidatePath('/', 'layout')`.

**Estado previo (hallazgo):**

1. El conmutador funciona de extremo a extremo (setea cookie + `router.refresh()`).
2. La **landing pública**, los **headers**, `login`, `apply`, `qualify` y
   `courses/*` ya leen el diccionario (≈ cobertura alta).
3. **Todo el interior de la app NO lo lee**: `app/dashboard/*`,
   `components/dashboard/*`, `components/courses/*`, `components/admin/*`,
   `app/dashboard/admin/*` contienen **texto en español hardcodeado**.
4. Las **competencias** (`types/progress.ts` → `COMPETENCY_LABELS`) y los **niveles
   profesionales** están hardcodeados en español.
5. El **contenido de cursos** (títulos/descripciones de módulos, títulos de
   lecciones) se lee directo de Supabase en español; no existen columnas
   traducidas.
6. El subsistema i18n **no está documentado** en `docs/` (causa raíz de la
   implementación incompleta).

Este documento especifica los requisitos para corregir los puntos 3–6 dentro del
alcance definido en 1.2.

### 2.2 Product Functions

Funciones objeto de esta SRS:

- Conmutar idioma entre ES/EN y que **toda** la aplicación refleje el idioma
  activo (persistencia por cookie, detección por `accept-language` en primera
  visita).
- Renderizar la carcasa de UI del dashboard, cursos, lecciones, tracker, grading,
  progreso profesional y admin desde el diccionario tipado.
- Resolver títulos/descripciones de módulos y lecciones por idioma con fallback
  al español.
- Permitir a los administradores editar los títulos traducidos (`_en`) desde el
  panel de administración.
- Localizar competencias y niveles profesionales.
- Garantizar paridad tipada entre las ramas `es` y `en` del diccionario (sin
  drift de claves).

### 2.3 Product Constraints

- **Stack fijo:** Next.js 15 (App Router, RSC + Server Actions), React 19,
  TypeScript `strict`, Tailwind v4, Supabase (Postgres 17.6). No se introducen
  ORMs ni librerías i18n externas.
- **Rendering:** las páginas del dashboard son Server Components; los componentes
  cliente deben obtenerse el idioma vía contexto `useLanguage()` o props, nunca
  vía fetches/fetch al backend.
- **Regla de performance (Vercel Best Practices):** `React.cache` para deduplicar
  lecturas del diccionario, `Promise.all` para lecturas paralelas, cero
  regresión de bundle (las cadenas deben ser tree-shakeable o venir del servidor).
- **Seguridad:** el contenido de cursos sigue siendo editable solo por admin
  (RLS + Admin client). La cookie de idioma debe mantener `secure` en producción.
- **Regla "source of truth":** ante discrepancia entre docs y código, prevalece
  el **código real** (AGENTS.md). La SRS asume que existan columnas como
  `modules.description`; el ejecutor debe verificar el esquema real antes de la
  migración (5.A).

### 2.4 User Characteristics

| Clase | Rol | Idioma de uso | Impacto |
|-------|-----|---------------|---------|
| Estudiante | `student` | ES (mayoría) y EN | Consume cursos/tracker/progreso; requiere toda la UI en su idioma |
| Instructor | `instructor` | ES/EN | Grading; requiere etiquetas de calificación traducidas |
| Admin | `admin` | ES/EN | Panel de administración; requiere UI + edición de títulos traducidos |
| Visitante anónimo | — | `accept-language` | Landing, cursos, qualify, login |

### 2.5 Assumptions and Dependencies

- **Supuesto A1:** el contenido *autoría* de las lecciones (HTML rich-text) y el
  feedback de IA se mantienen en español en esta iteración (validado con el
  cliente).
- **Supuesto A2:** los títulos de contenido (`modules.title`, `modules.description`,
  `lessons.title`) son cadenas cortas y traducibles por el admin sin intervención
  de traductores externos.
- **Dependencia D1:** la persistencia de idioma por cookie y el re-render vía
  `router.refresh()` siguen siendo el mecanismo de cambio de idioma (no URL).
- **Riesgo R1:** `docs/DATABASE.md` está desactualizado respecto al esquema real
  de `modules`/`lessons` — el ejecutor debe confirmar columnas antes de migrar.
  Impacto si es falso: la migración podría apuntar a columnas inexistentes.

### 3.1 External Interfaces

#### 3.1.1 User Interfaces

- REQ-INT-004 (Interfaz UI — conmutador)
  - **Statement:** El conmutador de idioma (`LanguageSwitcher`) deberá seguir
    visible en toda la aplicación (incluido el dashboard vía
    `FloatingLanguageSwitcher`) y deberá reflejar visualmente el idioma activo en
    todo momento.
  - **Rationale:** Es el único punto de cambio manual de idioma del usuario.
  - **Acceptance Criteria:** Al cambiar a EN, todas las pantallas del dashboard
    actualizan sus textos; el botón "EN" queda resaltado; el `aria-label` y los
    textos internos del conmutador usan el idioma activo.
  - **Verification Method:** Demonstration.

#### 3.1.2 Hardware Interfaces

No aplica.

#### 3.1.3 Software Interfaces

- REQ-INT-001 (Contrato del Diccionario tipado)
  - **Statement:** El tipo `Dictionary` deberá estar definido por una **única
    forma** (`DictionaryShape`) de modo que TypeScript obligue que las ramas `es`
    y `en` tengan exactamente las mismas claves, y `getDictionary(language)`
    devuelva esa forma. Se deberá declarar
    `const dictionaries: Record<Language, DictionaryShape> = {...} as const`
    satisfaciendo `DictionaryShape`.
  - **Rationale:** Hoy `Dictionary = (typeof dictionaries)[Language]` es la
    *unión* de dos literales independientes, lo que no impide que una rama pierda
    u omita claves (drift es/en).
  - **Acceptance Criteria:** Quitar una clave de una sola rama produce error de
    compilación. `getDictionary` devuelve un tipo único estable para todas las
    páginas RSC y clientes.
  - **Verification Method:** Analysis (type-check) + Test (build `tsc`).

- REQ-INT-002 (Contrato del Server Action de idioma)
  - **Statement:** El sistema deberá conservar `setLanguagePreference(language)`
    firmando `(rawLanguage: string) => Promise<{ language: Language }>`, validando
    contra `isSupportedLanguage`, persistiendo la cookie `preferred_language`
    (`path: '/'`, `sameSite: 'lax'`, `secure: NODE_ENV === 'production'`,
    `maxAge: 1 año`) e invocando `revalidatePath('/', 'layout')`.
  - **Rationale:** Es el contrato de persistencia del idioma; no debe cambiar su
    forma pública.
  - **Acceptance Criteria:** Un valor no soportado cae a `DEFAULT_LANGUAGE`; la
    cookie persiste y el siguiente request server-side lee el idioma correcto.
  - **Verification Method:** Test.

- REQ-INT-003 (Contrato de lectura de contenido localizado)
  - **Statement:** Las consultas de `modules` y `lessons` deberán seleccionar las
    columnas traducidas (`title_en`, `description_en`, `title_en`) además de las
    base, y los componentes deberán resolver el valor visible con una función de
    fallback `pick(language, { es: title, en: title_en })` (o equivalente) que
    devuelve la traducción cuando `language === 'en'` y `_en` no es
    `null`/`''`, y el español en caso contrario.
  - **Rationale:** Separa la fuente de datos (BD) de la decisión de idioma (UI).
  - **Acceptance Criteria:** Con `language='en'`, un módulo con `title_en` poblado
    muestra el título en inglés; con `title_en` nulo muestra `title` en español.
  - **Verification Method:** Test (unit) + Demonstration.

### 3.2 Functional

- REQ-FUNC-001 (Cobertura de diccionario — dashboard hub)
  - **Statement:** La página `/dashboard` deberá renderizar todos sus textos
    visibles (título/descripción de las 4 tarjetas "Programa de Formación",
    "Seguimiento y Evaluación", "Progreso Profesional", "La Academia", y el
    "Panel de Gestión") desde el diccionario.
  - **Rationale:** Es la pantalla principal del estudiante y está 100% hardcodeada.
  - **Acceptance Criteria:** En `en` no aparece ninguna palabra visible en español.
  - **Verification Method:** Inspection + Test.

- REQ-FUNC-002 (Cobertura de diccionario — lista de cursos)
  - **Statement:** `CourseListView` y `app/dashboard/courses/*` deberán traducir
    "PROGRAMA DE FORMACIÓN", el subtítulo, "MÓDULO {n}", "ESTADO:", "En progreso",
    "Bloqueado", el fallback "Contenido esencial para tu formación.", el estado
    vacío "No hay módulos disponibles aún." y el CTA "PONER EN PRÁCTICA MI
    FORMACIÓN".
  - **Rationale:** Texto hardcodeado en un `"use client"` component.
  - **Acceptance Criteria:** Todas las cadenas listadas provienen del diccionario
    (o contexto), en `es` y `en`.
  - **Verification Method:** Inspection + Test.

- REQ-FUNC-003 (Cobertura de diccionario — reproductor de lección)
  - **Statement:** La página de lección (`[courseId]/[lessonId]`) y sus
    componentes (`CourseSidebar`, `VideoPlayer`, `LessonContent`) deberán traducir
    los textos fijos: "LECCIONES", "MÓDULO {n}", "MICRO TEXTO OPCIONAL",
    "UNIDAD AUDIOVISUAL", "Sin descripción disponible.", "REFERENCIAS VISUALES",
    "SIGUIENTE LECCIÓN", "LECCIÓN ANTERIOR", "Fin del módulo", "Volver" y
    encabezados de navegación.
  - **Rationale:** Reproductor con texto fijo en español.
  - **Acceptance Criteria:** Ningún texto fijo visible aparece en español cuando
    el idioma es `en`.
  - **Verification Method:** Inspection + Test.

- REQ-FUNC-004 (Cobertura de diccionario — tracker)
  - **Statement:** `app/dashboard/tracker/*` (`SubmissionForm`, `SubmissionCard`,
    `FeedbackModal`, `page`) deberá traducir etiquetas de formulario, estados
    ("Pendiente"/"Revisado"), botones, placeholders y textos de feedback.
  - **Rationale:** Funcionalidad crítica del estudiante hardcodeada.
  - **Acceptance Criteria:** Comportamiento idéntico con cadenas según idioma.
  - **Verification Method:** Inspection + Test.

- REQ-FUNC-005 (Cobertura de diccionario — grading)
  - **Statement:** `app/dashboard/grading/*` (`GradingCard`, `page`) deberá
    traducir sliders, etiquetas de criterios (fade/limpieza/técnica/simetría),
    mensajes de puntuación y botones de acción.
  - **Rationale:** Libro de calificación del instructor.
  - **Acceptance Criteria:** UI de grading en inglés cuando `language='en'`.
  - **Verification Method:** Inspection + Test.

- REQ-FUNC-006 (Cobertura de diccionario — admin)
  - **Statement:** Las páginas y componentes de administración
    (`admin/courses/*`, `admin/gestion_users/*`, `admin/leads/*`,
    `admin/lessons/edit/*`, `components/admin/*` — `RichTextEditor`,
    `EditorToolbar`, `EditableText`, `AdminCourseList`) deberán traducir sus
    textos fijos.
  - **Rationale:** Panel de gestión para admin; debe ser bilingüe.
  - **Acceptance Criteria:** Panel de admin coherente en `es` y `en`.
  - **Verification Method:** Inspection + Test.

- REQ-FUNC-007 (Columnas traducidas — módulos)
  - **Statement:** La tabla `modules` deberá exponer `title_en` y `description_en`
    (tipo `text`, `NULL` permitido, sin romper RLS existente).
  - **Rationale:** Almacenar la traducción del título/descripción de módulo.
  - **Acceptance Criteria:** Migración aplicable de forma idempotente; `title_en`
    y `description_en` seleccionables y editables por admin.
  - **Verification Method:** Analysis (DDL) + Test (migración).

- REQ-FUNC-008 (Columnas traducidas — lecciones)
  - **Statement:** La tabla `lessons` deberá exponer `title_en` (`text`, `NULL`
    permitido).
  - **Rationale:** Título de lección traducible. El `content` (HTML) queda
    **excluido** (diferido).
  - **Acceptance Criteria:** `title_en` seleccionable y editable por admin.
  - **Verification Method:** Analysis (DDL) + Test.

- REQ-FUNC-009 (CRUD admin de títulos traducidos)
  - **Statement:** Las Server Actions y los formularios de administración de
    cursos/lecciones deberán permitir crear y editar los valores `_en` de
    módulos (`title_en`, `description_en`) y lecciones (`title_en`), además del
    valor español actual, sin alterar la lógica de `order_index`/`competency`.
  - **Rationale:** El admin necesita mantener las traducciones.
  - **Acceptance Criteria:** Crear/editar un registro con `title_en` poblado lo
    persiste y lo muestra en `en`.
  - **Verification Method:** Test + Demonstration.

- REQ-FUNC-010 (Localización de competencias y niveles)
  - **Statement:** Los nombres de competencias (`COMPETENCY_LABELS`) y de niveles
    profesionales (`PROFESSIONAL_LEVELS`), y los estados derivados
    ("Completado/Competente/En Progreso/Sin Iniciar"), deberán resolverse por
    idioma activo en `progreso_profesional` (y en cualquier lugar que los use),
    moviendo las etiquetas a una fuente localizable por idioma.
  - **Rationale:** Hoy están en `types/progress.ts` y la página como literales ES.
  - **Acceptance Criteria:** En `en` la página de progreso muestra competencias y
    niveles en inglés, manteniendo el cálculo de % intacto.
  - **Verification Method:** Test + Demonstration.

### 3.3 Quality of Service

#### 3.3.1 Performance

- REQ-PERF-001 (Sin regresión de bundle)
  - **Statement:** La traducción de la carcasa del dashboard no deberá aumentar
    el JavaScript enviado al cliente para páginas RSC puras (ej.
    `progreso_profesional` debe permanecer en 0 JS de componente), y los
    componentes cliente deberán leer las cadenas desde el contexto `useLanguage`
    (importación tree-shakeable del diccionario) o props, sin fetches adicionales.
  - **Verification Method:** Analysis (bundle) — `next build` y revisión de
    tamaño de JS por ruta.

- REQ-PERF-002 (Lecturas paralelas y cacheadas)
  - **Statement:** Las lecturas que ahora incluyen columnas `_en` deberán seguir
    respetando `Promise.all` para fuentes independientes y `React.cache` para
    helpers por request; no se deberá introducir `await` secuencial innecesario.
  - **Verification Method:** Analysis (inspection de código).

#### 3.3.2 Security

- REQ-SEC-001 (Escritura de títulos traducidos solo admin)
  - **Statement:** La creación/edición de `title_en`/`description_en` deberá
    seguir el patrón existente de autorización (verificar sesión y rol con cliente
    normal → mutar con Admin client), sin degradar RLS.
  - **Verification Method:** Test (intento no-admin rechazado).

- REQ-SEC-002 (Cookie de idioma)
  - **Statement:** La cookie `preferred_language` deberá mantenerse con
    `sameSite: 'lax'`, `secure` en producción, y no deberá contener información
    sensible; el valor se valida contra `SUPPORTED_LANGUAGES`.
  - **Verification Method:** Analysis.

#### 3.3.3 Reliability

- REQ-REL-001 (Fallback determinista)
  - **Statement:** Ante una traducción `_en` ausente (`NULL` o cadena vacía), el
    sistema deberá mostrar la variante en español de forma determinista (sin
    errores ni render vacío).
  - **Verification Method:** Test.

#### 3.3.4 Availability

No aplica cambio (se hereda del sistema).

#### 3.3.5 Observability

- REQ-OBS-001 (Reporte de cobertura)
  - **Statement:** El equipo deberá disponer de un medio (script/lint o comando)
    para detectar cadenas hardcodeadas en español en archivos `app/` y

### 5.E Instrucciones Estructurales para El Ejecutor

1. **No migres a librería externa.** Conserva el diccionario tipado propio y el
   mecanismo cookie + `accept-language` ya existente.
2. **Amplía el diccionario primero** (ramas `es` y `en`), aplicando el contrato
   `DictionaryShape` (REQ-INT-001) para que TS fuerce paridad es/en.
3. **RSC primero:** en las páginas server, usa `const dict = await
   getServerDictionary()` y pasa solo las cadenas necesarias a hijos client
   (`server-serialization`). En componentes client, usa `useLanguage()`.
4. **Columnas `_en`:** aplica el DDL 5.D, actualiza los `select` de
   `cache-helpers` y de las páginas, e implementa un único helper de fallback
   (`lib/i18n/`) (REQ-REUSE-001).
5. **Admin CRUD:** añade campos `_en` a formularios y Server Actions de
   `admin/courses` y `admin/lessons/edit`; respeta auth + Admin client + Zod.
6. **Competencias/niveles:** mueve `COMPETENCY_LABELS` y `PROFESSIONAL_LEVELS` a
   una fuente localizable por idioma (REQ-FUNC-010) sin alterar el cálculo de %.
7. **Performance:** `Promise.all` + `React.cache`, sin awaits secuenciales, sin
   impacto de bundle en páginas RSC puras (REQ-PERF-001/002).
8. **Documenta:** actualiza `docs/ARCHITECTURE.md` (i18n), `docs/COMPONENTS.md`,
   `docs/DATABASE.md` (columnas `_en`), `docs/ROUTES.md` si cambian
   dependencias de datos, y `.ai/PROJECT_CONTEXT.md` (cierre de sesión).
9. **No traduzcas** HTML de lecciones ni feedback IA (REQ-ML-001, diferido).
