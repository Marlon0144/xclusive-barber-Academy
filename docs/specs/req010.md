# CRUD de administración para títulos traducidos (`title_en`/`description_en`)

## Statement

The system shall permitir a los administradores crear y editar los valores
traducidos `title_en` y `description_en` de `modules`, y `title_en` de `lessons`,
desde el panel de administración, además del valor en español existente, sin
alterar la lógica de orden (`order_index`) ni de competencia (`competency`). Las
mutaciones shall verificar sesión y rol `admin` con el cliente normal, mutar con
el cliente Admin, validar con Zod y revalidar la ruta.

## Rationale

Sin campos de edición, los títulos `_en` no podrían mantenerse operativamente; la
columna quedaría siempre nula y la app seguiría visible en español para `en`.

## Acceptance Criteria

- [ ] Las Server Actions de `app/dashboard/admin/courses/actions.ts` aceptan
      parámetros `titleEn`/`descriptionEn` (módulo) y `titleEn` (lección) para
      `createModule`, `updateModuleTitle`, `createLesson`, `updateLessonTitle`.
- [ ] Las acciones validan entrada con **Zod** (`z.string().max(...)`, opcional),
      autentican (`getUser` + verificación de rol `admin` vía cliente normal) y
      mutan con `createAdminClient()`.
- [ ] La UI (`AdminCourseList`, `RichTextEditor`/`EditLessonForm` o componente
      equivalente) expone campos para editar los valores EN; los valores vacíos se
      guardan como `null` (para activar el fallback ES).
- [ ] `updateModuleCompetency` y `reorderLessonsInModule` no se ven afectadas.
- [ ] `revalidatePath` se ejecuta tras cada mutación (patrón existente).

## Acceptance Criteria (seguridad)

- [ ] Un usuario no-admin no puede mutar `title_en`/`description_en` (rechazado/error).
- [ ] Se usa cliente normal para autorizar y Admin client solo para mutar
      (regla de oro "verificar primero, mutar después").

## Verification Method

Test (Server Action admin vs no-admin) + Demonstration (CRUD en UI).
