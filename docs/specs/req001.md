# Contrato tipado del Diccionario (DictionaryShape) + paridad es/en

## Statement

The system shall definir el tipo exportado `Dictionary` a partir de una **única
forma** `DictionaryShape`, de modo que TypeScript obligue a que las ramas `es` y
`en` de `lib/i18n/dictionaries.ts` tengan exactamente las mismas claves, y
`getDictionary(language)` devuelva esa forma única y estable. El sistema shall
declarar `const dictionaries: Record<Language, DictionaryShape> = { es: {...}, en: {...} }`.

## Rationale

Hoy `export type Dictionary = (typeof dictionaries)[Language]` produce la
*unión* de dos tipos literales independientes; TypeScript no impide que una rama
pierda u omita claves. Ese "drift" es/es-en es parte de la causa raíz de la
implementación incompleta: no hay garantía en tiempo de compilación de que todo
texto traducido exista en ambos idiomas. Con `DictionaryShape` la paridad queda
forzada y cualquier clave faltante rompe el build (`tsc`).

## Acceptance Criteria

- [ ] Existe `type DictionaryShape = { ... }` (o interfaz) que describe TODAS las
      secciones del diccionario, incluidas las nuevas `dashboard`, `competencies`
      y `levels`.
- [ ] `dictionaries` se declara como `Record<Language, DictionaryShape>` y
      compila sin error.
- [ ] Quitar una clave de solo una rama (`es` o `en`) produce **error de
      compilación** en `tsc --noEmit`.
- [ ] `getDictionary(language: Language): Dictionary` (ahora `DictionaryShape`)
      devuelve un tipo único estable; el valor en runtime es el objeto de la rama
      correspondiente.
- [ ] No se rompe el uso existente `dictionary.landing.*`,
      `dictionary.actions.*`, `dictionary.languageSwitcher.*`, etc.

## Verification Method

Analysis (type-check con `tsc --noEmit`) + Test (`next build` completo).

## More Information

- SRS: `docs/specs/srs001.md` §3.1.3 (REQ-INT-001) y §5.C (forma propuesta).
- Archivo principal: `lib/i18n/dictionaries.ts`.
- Consumidores: `lib/i18n/server.ts` (`getServerDictionary`), todos los
  componentes/páginas que leen `dictionary.*`.
- Regla de performance: la paridad tipada NO debe añadir JavaScript al cliente;
  las ramas deben ser tree-shakeable (importadas estáticamente).
- Relacionado: REQ-MAINT-002 (no hardcoded strings).
